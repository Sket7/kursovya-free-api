# Dependency Injection с Koin

Ветка `di-koin` демонстрирует построение приложения через контейнер зависимостей Koin 4.1.0.

## Границы первого блока

- `RickAndMortyApplication` один раз запускает Koin для всего процесса приложения.
- `infrastructureModule` создаёт singleton-экземпляры Retrofit API и Room database.
- `repositoryModule` связывает интерфейсы репозиториев с их реализациями.
- Реализации получают зависимости через конструктор и ничего не знают о способе их создания.
- Сетевой кеш и пользовательские заметки используют общую data-основу из `main`.

## Presentation-модуль

- ViewModel списков объявлены через `viewModel` и получают `CatalogRepository` по интерфейсу.
- ViewModel деталей создаются Koin с runtime-параметром `id` и внедрёнными репозиториями.
- `CommentsViewModel` получает локальный репозиторий заметок из контейнера.
- Жизненный цикл ViewModel остаётся под управлением AndroidX; Koin отвечает только за построение
  графа объектов.

## Compose и навигация

- `DiApp` получает ViewModel через `koinViewModel()` вместо ручного создания.
- Navigation 3 предоставляет отдельный `ViewModelStore` каждой back-stack entry.
- Для деталей `parametersOf(route.id)` передаёт навигационный ID в соответствующее Koin-определение.
- View остаются тонкими binding-компонентами и передают состояние в общий stateless UI из
  `ui.shared`, поэтому внешний вид совпадает с остальными архитектурными ветками.

## Поток зависимостей

`Application → Koin modules → API/Room → Repository interfaces → ViewModel → Compose View`

Репозитории используют стратегию cache-first с последующим обновлением из API. Связанные ресурсы
загружаются batch-запросами, изображения кеширует Coil, а пользовательские оценки, отметки просмотра
и комментарии хранятся отдельно в Room.

## Возможности

- главный экран, списки и детали эпизодов, персонажей и локаций;
- серверные поиск, фильтры, debounce и пагинация;
- переходы между связанными ресурсами;
- просмотрено, оценка 1–5 и локальный комментарий;
- отдельный офлайн-экран личных комментариев;
- loading, empty, error, cached/offline состояния.
