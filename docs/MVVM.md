# MVVM-реализация

Ветка `mvvm` реализует то же приложение в варианте Model–View–ViewModel.

## Границы

- `mvvm/data` — Repository координирует общие Retrofit API, Room DAO и кеш.
- `mvvm/presentation` — AndroidX `ViewModel` хранит `StateFlow` состояния экрана, принимает события и
  запускает операции в `viewModelScope`.
- `mvvm/view` — тонкий Compose binding получает ViewModel, lifecycle-aware наблюдает состояние и
  передаёт его в общие stateless-компоненты `ui.shared`.
- `mvvm/navigation` — типобезопасные маршруты Navigation 3.

Зависимости создаются вручную в composition root. Koin не используется: он является предметом
отдельной ветки `di-koin`.

## Жизненный цикл и навигация

Каждая Navigation 3 back-stack entry получает собственные `SaveableStateHolder` и
`ViewModelStore`. Поэтому ViewModel деталей создаётся для конкретного ID, переживает изменение
конфигурации и очищается после удаления destination из back stack. Compose наблюдает `StateFlow`
через `collectAsStateWithLifecycle`.

## Кеширование

Repository использует стратегию stale-while-revalidate: сначала публикуется кеш Room, затем
выполняется обновление из API. При ошибке сети кеш остаётся доступным. Страницы сохраняют метаданные
пагинации, фильтры и исходный порядок. Связанные сущности загружаются batch-запросами, изображения
кеширует Coil, а оценки и комментарии живут в отдельной таблице Room.

## Возможности

- главный экран, каталоги и детали эпизодов, персонажей и локаций;
- серверные поиск, фильтры, debounce и пагинация;
- переходы между связанными ресурсами;
- просмотрено, оценка 1–5 и локальный комментарий;
- отдельный офлайн-экран личных комментариев;
- единый интерфейс из `ui.shared` со всеми остальными архитектурами.
